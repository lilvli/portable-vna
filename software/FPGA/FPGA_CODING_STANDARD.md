# 便携式直采矢量网络分析仪 FPGA 编码规范

- 文档版本：V1.1
- 生效日期：2026-08-10
- 适用目录：`software/FPGA/`
- 工具基线：Vivado 2025.2
- 目标器件：`xcku5p-ffvb676-2-i`
- 关联路线：`SOFTWARE_IMPLEMENTATION_ROADMAP.md`

## 1. 目的与适用范围

本规范用于约束本项目的手写 RTL、仿真代码、约束、Tcl 脚本、IP 配置和交接记录，目标是：

1. 代码注释充分，后来者能看懂设计意图、接口和验证边界。
2. 层次清晰，各模块只承担一类职责，避免把时钟、配置、JESD、算法和调试堆在一个顶层中。
3. 优先使用 AMD/Xilinx 官方 IP、XPM 和器件原语，减少手写高速协议与器件专用逻辑的风险。
4. 格式统一、代码整齐，便于审查、仿真、综合和问题定位。
5. 每个阶段都留有可重复的验证入口，不把“能生成 bitstream”描述成“真实硬件已验证”。
6. 达到生产级、大型研发团队可审查和可复用的质量，领导或其他项目接手时无需依赖原作者的口头解释。

本规范中的关键词含义：

- **必须**：不满足时不得合入正式设计。
- **禁止**：除非有书面例外说明并经软件总体负责人确认，否则不得采用。
- **建议**：默认采用；若偏离，应在模块说明或任务交接中写明原因。

## 2. 当前项目实现基线

以下参数作为当前实施基线。后续若硬件或产品方案变化，必须先更新基线文档，再修改代码。

| 项目 | 当前基线 |
|---|---|
| FPGA | XCKU5P-FFVB676-2-I |
| RTL | 手写生产 RTL 优先使用 Verilog-2001，文件扩展名 `.v` |
| 仿真 | 测试平台允许使用 SystemVerilog，文件扩展名 `.sv` |
| 时钟芯片 | LMK04828，板载 50 MHz TCXO 输入 |
| FPGA/JESD 时钟 | 125 MHz |
| ADC | AD9250，双通道 14 bit，250 MSPS |
| ADC JESD | M=2、L=2、F=2、K=32、N=14、NP=16、Subclass 1、2×5 Gb/s |
| DAC | AD9144，Mode 4，双通道有效数据，2×插值 |
| DAC JESD | M=2、L=4、F=1、K=32、N=NP=16、Subclass 1、4×10 Gb/s |
| SYSREF | 3.90625 MHz，当前基线为连续模式 |
| ADC lane | 物理 CH3→logical lane0，CH2→logical lane1 |
| DAC lane | 物理 CH0..CH3→logical lane3..0，即 `[3,2,1,0]` |

## 3. 推荐目录结构与职责边界

正式开发逐步整理为以下结构。Vivado 自动生成目录不得充当源代码目录。

```text
software/FPGA/
├─ README.md                 # 工程入口、构建方法和当前状态
├─ FPGA_CODING_STANDARD.md   # 本规范
├─ SOFTWARE_IMPLEMENTATION_ROADMAP.md
├─ architecture/             # 总体架构、数据流、时钟复位和接口说明
├─ constraints/              # 顶层 XDC 和约束说明
├─ config/                   # LMK/ADC/DAC 配置源、解码表和生成器
├─ ip/                       # XCI 与可重复创建 IP 的 Tcl
├─ rtl/
│  ├─ clock_reset/           # 时钟、复位和启动控制
│  ├─ control/               # SPI、寄存器、配置状态机
│  ├─ jesd_tx/               # AD9144 TX 的 IP 封装和接口适配
│  ├─ jesd_rx/               # AD9250 RX 的 IP 封装和接口适配
│  ├─ datapath/              # NCO、DDC、积分、复数数据通路
│  ├─ interfaces/            # UART/以太网/寄存器与数据帧适配
│  └─ top/                   # 板级端口和系统集成，不放复杂算法
├─ sim/                      # 自检测试平台、模型、波形脚本
├─ scripts/                  # 创建工程、生成 IP、仿真和构建 Tcl
├─ tasks/                    # 分阶段任务、结果和交接记录
└─ output/                   # 可删除的本地生成物，不作为受控源
```

模块职责必须单一。例如：

- SPI 主机只负责 SPI 时序，不解释 LMK/ADC/DAC 的业务含义。
- 配置管理器负责设备顺序、延时、读回和错误，不直接实现 SPI 边沿。
- JESD 封装负责 IP 接口、lane 重排和状态汇总，不放 VNA 校准算法。
- 数据通路负责样本、复数运算和积分，不直接操作 UART 字节流。
- 顶层只完成板级缓冲、模块连接、安全门控和少量状态汇总。

## 4. 官方 IP、XPM 与原语优先规则

### 4.1 选择顺序

实现一个功能时，按以下顺序选择：

1. Vivado 官方 IP。
2. XPM 宏。
3. AMD/Xilinx 官方器件原语。
4. 已在本项目或受控参考工程中验证过的手写模块。
5. 新写 RTL。

### 4.2 必须优先使用官方实现的功能

| 功能 | 首选实现 |
|---|---|
| JESD204 TX/RX | Vivado JESD204 IP |
| JESD 物理层、GTY、PLL | JESD204 PHY / GT Wizard |
| 时钟生成 | Clocking Wizard、BUFG/IBUFDS_GTE4 等官方原语 |
| CDC | `xpm_cdc_single`、`xpm_cdc_handshake`、`xpm_cdc_pulse`、`xpm_cdc_gray` |
| 异步 FIFO | XPM FIFO、FIFO Generator 或 AXI4-Stream Data FIFO |
| RAM/ROM | XPM Memory 或 Block/Distributed Memory Generator |
| 在线调试 | ILA、VIO |

禁止在没有充分论证时手写以下核心：

- JESD204 CGS、ILAS、链路层和 8b/10b；
- GTY COMMON/CHANNEL、PLL 选择和高速串行复位流程；
- 通用异步 FIFO；
- 大容量 RAM/ROM；
- 多位异步总线的直接采样逻辑。

### 4.3 IP 管理要求

每个正式 IP 必须记录：

- IP 名称、版本和 Vivado 版本；
- 目标 part；
- 关键参数、时钟和数据宽度；
- 许可证状态；
- 创建或重建 Tcl；
- 仿真和独立综合入口；
- 与外部模块的接口说明。

必须保存 `.xci` 和可重复创建 Tcl；不得手工修改 IP output products，不得直接复制厂家 Demo 的旧 XCI、GT 原语、LOC 或时钟选择常量。

## 5. 源文件与格式规范

1. 手写文本文件统一使用 UTF-8、无 BOM、LF 换行、文件末尾保留一个换行。
2. 缩进统一为 4 个空格，禁止 Tab。
3. 一行建议不超过 120 个字符；长端口、表达式或实例连接应按逻辑分行。
4. 禁止行尾空格；禁止连续多行空白。
5. 一行只声明一个逻辑组；不同职责的信号不得挤在一行。
6. 端口、参数、实例连接和状态表必须垂直对齐，便于比较。
7. 手写 RTL 建议在文件开头使用 `` `default_nettype none``，文件末尾恢复 `` `default_nettype wire``，防止拼写错误生成隐式网络。
8. 不得依赖未说明的 Vivado GUI 状态；关键工程设置必须能由 XCI、XDC 或 Tcl 复现。

## 6. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 文件/模块 | 小写下划线，模块名与文件名一致 | `ad9250_transport_unpack.v` |
| 参数 | 大写下划线 | `CLK_FREQ_HZ`、`DATA_WIDTH` |
| 本地常量 | 大写下划线 | `STATE_WAIT_LOCK` |
| 普通信号 | 小写下划线 | `sample_valid` |
| 输入/输出端口 | 后缀 `_i` / `_o`；双向 `_io` | `reset_n_i`、`link_ready_o` |
| 低有效信号 | 后缀 `_n` 或 `_ni/_no` | `reset_ni`、`cs_no` |
| 差分信号 | 后缀 `_p/_n` | `fpga_sysref_p` |
| 时钟 | 前缀 `clk_` 或后缀 `_clk`，必须体现频率/域 | `clk_mgmt_100m` |
| 复位 | 体现时钟域和有效电平 | `rst_tx_250m_n` |
| 实例 | 前缀 `u_` | `u_ad9250_rx` |
| 生成块 | 前缀 `g_` | `g_lane` |
| 状态机 | `state_*` / `next_state_*` | `state_cfg` |
| 计数器 | 后缀 `_cnt` | `timeout_cnt` |
| 粘性错误 | 后缀 `_sticky` | `jesd_error_sticky` |

时钟域不同但名称相同的状态必须带域后缀，例如 `_mgmt`、`_tx`、`_rx`，不得只靠注释区分。

## 7. 注释规范

注释必须多，但重点是解释“为什么、依据、边界和风险”，不能只把代码重新翻译成中文。

### 7.1 每个手写文件必须有文件头

```verilog
// ============================================================================
// File        : module_name.v
// Project     : Portable Direct-Sampling VNA
// Module      : module_name
// Description : 一句话说明模块责任和不负责的内容。
//
// Clock domains:
//   - clk_mgmt_100m_i : 配置和状态域
//
// Reset:
//   - rst_mgmt_n_i    : 低有效，异步置位、同步释放
//
// Interfaces:
//   - 上游接口的数据宽度、握手和样本顺序
//   - 下游接口的数据宽度、握手和错误语义
//
// Key assumptions:
//   - 参数来源、固定频率、lane 映射和依赖 IP
//
// Verification:
//   - 对应 testbench、综合入口和尚未执行的硬件验证
// ============================================================================
```

### 7.2 必须注释的位置

- 每个模块的责任、输入输出、时钟域、复位方式和验证边界；
- 每组端口的方向、有效电平、数据格式、样本顺序和握手规则；
- 每个跨时钟信号采用哪种 CDC，以及为什么；
- 每个状态机的状态含义、进入条件、退出条件、超时和错误去向；
- 所有协议常数、寄存器值、lane 映射、位段和“魔法数字”的来源；
- 定点数的符号、小数位、舍入、饱和和溢出策略；
- 复杂组合逻辑、流水线延迟、背压传播和对齐关系；
- IP 实例的用途、版本、关键参数和接口宽度；
- 暂时保留的限制、TODO 和硬件风险。

### 7.3 注释质量要求

- 修改代码时必须同步更新相邻注释和文档。
- 禁止保留 Vivado 默认的空白文件头字段。
- 禁止写“这里加一”“等待一下”之类没有设计依据的注释。
- TODO 必须写明完成条件，例如：`TODO(HW): 获得实测 LMK lock 时间后冻结超时值`。
- 注释不得把仿真、综合、实现或 bitstream 生成描述成真实硬件通过。

## 8. RTL 编码规则

### 8.1 时序与组合逻辑

1. 时序逻辑使用非阻塞赋值 `<=`。
2. 组合逻辑使用阻塞赋值 `=`，并为所有输出提供默认值，禁止推断非预期锁存器。
3. 一个时序 `always` 块原则上只属于一个时钟域和一种复位语义。
4. 禁止用普通逻辑生成新时钟；使用 Clocking Wizard、MMCM/PLL 和 BUFG 系列资源。
5. 禁止把数据当时钟或把时钟当普通数据门控。
6. 流水线延迟必须在注释或接口文档中明确，以拍数表示。

### 8.2 位宽、符号与算术

1. 常量必须写明位宽和进制，如 `16'h0001`，禁止无意使用 32-bit 有符号整数。
2. 有符号数必须显式声明 `signed`，跨位宽运算必须显式扩展或截断。
3. 定点乘法、累加和除法必须写明输入格式、内部保护位、舍入与饱和策略。
4. ADC 14-bit 样本进入算法前必须按二进制补码明确符号扩展到统一宽度。
5. 禁止依赖隐式 signed/unsigned 转换。

### 8.3 参数化与生成

1. 可复用模块应参数化时钟频率、数据宽度、超时和积分长度。
2. 参数必须有合法范围检查；仿真阶段对非法参数立即报错。
3. `generate` 块必须命名。
4. 生成文件必须由脚本生成，并支持 `--check` 或等价的一致性检查；禁止手工修改生成数据。

### 8.4 状态机

1. 状态名必须表达业务语义，不使用 `S0/S1/S2`。
2. 复位进入安全状态；异常和非法状态必须回到安全状态或错误状态。
3. 每个等待外部响应的状态必须考虑超时。
4. 状态输出、跳转条件和错误码必须可通过仿真或 ILA 观察。
5. 不使用 `casex`；使用普通 `case` 并提供 `default`。

## 9. 时钟、复位和 CDC 规则

1. 架构文档必须列出所有时钟源、频率、用途和时钟域关系。
2. 异步复位允许异步置位，但必须在每个目标时钟域同步释放。
3. 单 bit 稳态跨域使用 `xpm_cdc_single`。
4. 单次事件跨域使用 `xpm_cdc_pulse` 或握手机制。
5. 多 bit 配置跨域使用 `xpm_cdc_handshake`，保证 payload 相干。
6. 连续数据跨域使用官方异步 FIFO；禁止逐 bit 同步数据总线。
7. 计数值跨域应使用 Gray code、握手快照或 FIFO，不得直接采样二进制计数器。
8. CDC 的源域、目标域、更新频率和允许延迟必须写在实例上方。
9. ILA 只采集所在时钟域的信号；异步状态先同步再进入 ILA。

## 10. 流接口与控制接口规则

### 10.1 `valid/ready` 数据流

- 只有 `valid && ready` 时一次传输才完成。
- `valid=1 && ready=0` 时，数据和所有伴随字段必须保持不变。
- 不允许组合路径从下游 `ready` 穿过多个层次返回上游；必要时使用官方 FIFO 或寄存切片。
- 样本顺序必须在接口注释中标明“最低位是最早还是最晚”。

### 10.2 控制与状态

- 启动、清零、重试等命令应采用单拍脉冲或明确的请求/应答握手。
- `done`、`busy`、`ready`、`valid` 含义不得混用。
- 硬错误建议粘性保持，并配套错误码和明确清除条件。
- `all_config_done` 只表示配置事务完成，不等于时钟、JESD 或模拟链路已验证。

### 10.3 项目专用数据边界

- AD9144 每通道 64-bit 输入中，`[15:0]` 为本拍最早样本，`[63:48]` 为最晚样本。
- AD9250 每个 16-bit 容器中 `[13:0]` 为有效二进制补码样本，`[15:14]` 应为零/控制位。
- 复数数据统一明确实部、虚部、位宽、Q 格式和时间对应关系。
- 推荐同时保留复数 `R`、`A`，不要在 FPGA 内只保留最终 `S11`，便于校准重算和调试。

## 11. 约束与板级集成规则

1. XDC 必须引用原理图、FMC pin map 和 lane map，不从厂家 Demo 直接复制。
2. 所有普通 I/O 必须明确 `PACKAGE_PIN`、`IOSTANDARD` 和所属电源电压。
3. 时钟必须有真实来源和 `create_clock`；生成时钟优先由 IP 自带约束创建。
4. 禁止用宽泛 `false_path`、关闭 DRC 或降低严重等级来掩盖问题。
5. 输入/输出 delay 没有板级时序证据时不得编造；应在风险清单中保留。
6. GT COMMON、PLL、参考时钟和最终 lane LOC 必须由系统集成层统一负责。

## 12. 仿真、综合与验证门

每个模块必须尽早建立可重复验证，不等集成后才测试。

| 门 | 内容 | 最低要求 |
|---|---|---|
| G0 静态检查 | 编译、格式、参数、生成文件一致性 | 0 error；无未解释的关键 warning |
| G1 模块仿真 | 正常、边界、复位、背压、超时、错误恢复 | 自检输出明确 `PASS/FAIL` |
| G2 独立综合 | 目标 part 的 OOC/模块综合 | 0 error；资源和时钟合理 |
| G3 系统实现 | 完整综合、布局布线、时序、DRC、CDC | 时序满足；warning 逐项分类 |
| G4 硬件验证 | SPI、时钟、JESD、数据、模拟路径 | 独立记录实测条件和证据 |

要求：

- testbench 必须自动结束并返回明确结果，禁止只靠人工看波形判断。
- 每个状态机至少覆盖成功、超时、复位中断和非法响应。
- 算法模块使用可由 Python/MATLAB 生成的黄金向量交叉比较。
- 每次正式交接记录实际运行命令、结果和证据路径。
- bitstream 生成成功仅属于 G3，不能代替 G4。

## 13. 调试与可观测性

1. 每个关键模块应提供精简状态字，而不是把所有内部信号直接拉到顶层。
2. 关键错误应有粘性标志和饱和计数器。
3. ILA 按管理域、TX 域、RX 域和算法域分开，不跨域混采。
4. 首次调试至少观察：配置状态、PLL/GT reset done、JESD SYNC/SYSREF、链路 ready、样本 valid、削顶和 FIFO 错误。
5. ILA/VIO 是调试工具，不是最终用户接口，也不构成模拟性能证明。

## 14. 版本控制与生成物

必须受控：

- 手写 RTL、testbench、XDC、Tcl；
- IP `.xci` 和重建脚本；
- 配置源、生成器及生成结果的校验信息；
- 架构、接口、验证和交接文档。

不得作为正式源提交：

- `.Xil/`、`*.cache/`、`*.gen/`、`*.runs/`、`*.sim/`；
- 临时工程、日志、DCP、bitstream、ILA 数据；
- 未经核对的厂家 Demo 生成物。

## 15. 任务交接要求

每个阶段完成时至少记录：

- 实际完成和未完成内容；
- 修改文件；
- 时钟、复位、数据格式、握手和错误接口；
- 关键参数及来源；
- 仿真、综合、实现或硬件验证证据；
- warning、风险和下一步；
- 明确哪些硬件路径没有验证。

## 16. 禁止事项

- 禁止把全部功能长期堆积在 `top.v`。
- 禁止在未说明情况下复制厂家 Demo 的 XDC、IP、GT 原语或寄存器表。
- 禁止手工编写可由官方 IP/XPM 覆盖的高速协议核心。
- 禁止跨时钟域直接传多 bit 数据。
- 禁止使用无位宽常数和隐式符号转换完成关键算法。
- 禁止为通过时序而静默删除功能、关闭检查或添加宽泛假路径。
- 禁止只有代码没有注释、接口说明、testbench 和验证记录。
- 禁止把离线仿真、数字回环或文档审查称为真实 VNA 测量通过。

## 17. 生产级与“大厂风格”复用要求

本项目所称“大厂风格”，不是追求复杂框架或大量包装，而是做到：接口稳定、职责清楚、行为明确、证据完整、构建可重复、修改可审查、模块可独立移植。

### 17.1 接口先于实现

编写模块前必须先定义接口合同，至少写明：

- 模块负责什么、不负责什么；
- 每个端口的方向、位宽、单位、有效电平和复位值；
- 每个信号所属时钟域；
- 数据在什么条件下有效、何时允许变化；
- 延迟、吞吐量、背压和超时语义；
- 错误如何报告、保持和清除；
- 参数默认值、合法范围和改变参数后的影响。

禁止依赖以下隐藏条件：

- 上层实例名称或层次路径；
- ILA/VIO、`force` 或 GUI 手工操作才能正常运行；
- 未声明的全局宏、隐式网络或工程目录；
- 调用者必须“碰巧知道”的初始化顺序、脉冲宽度或数据格式。

正式接口一旦被其他模块使用，不得静默改变端口含义、位序、时序或错误语义。确需不兼容修改时，必须升级主版本并提供迁移说明。

### 17.2 模块化与复杂度控制

1. 一个手写生产 RTL 文件原则上只定义一个对外模块，文件名与模块名一致。
2. 一个模块只承担一个清晰职责；配置、协议、算法、CDC、调试和板级 I/O 不得无边界混写。
3. 手写生产模块建议不超过 500 行非注释代码；超过时必须审查能否按职责拆分，并记录保留大模块的理由。
4. 单个 `always` 块建议不超过 80 行可执行逻辑，条件嵌套建议不超过 3 层；超过时优先拆分组合判定、状态机或流水级。
5. 重复两次以上且语义相同的逻辑应评估提取为公共模块、函数或生成结构，禁止长期复制粘贴维护。
6. 参数化必须服务于真实复用场景，不为“看起来通用”引入难以验证的多余模式。
7. 公共模块不得硬编码本项目顶层信号名、本机绝对路径、个人目录或特定工程层次。

上述行数和嵌套数是代码评审触发线，不是为了满足数字而机械拆分；最终判断以职责、可读性和可验证性为准。

### 17.3 可读性与工程整洁度

- 标识符使用完整、稳定、业内通用的英文词汇；除 ADC、DAC、JESD、LMK、CDC、FIFO 等标准缩写外，禁止个人化缩写。
- 同一概念在全工程只能使用一套名称，例如不得混用 `rst_n`、`resetb`、`nreset` 表示同类接口。
- 端口按时钟/复位、控制、数据、状态、调试分组，并在声明和实例连接中保持相同顺序。
- 参数、端口、内部信号、组合逻辑、时序逻辑和实例按固定顺序组织，便于评审者快速定位。
- 禁止提交大段注释掉的旧实现、临时调试分支、无用途信号、空白默认文件头和失效 TODO。
- 禁止为了缩短代码使用难懂的一行式表达式；复杂条件应命名为含义清楚的中间信号。
- 对外状态、错误码和位域必须集中定义，禁止相同 bit 在不同文件中重复解释。

### 17.4 可复用模块交付包

计划被领导或其他项目复用的模块，不能只交付一个 `.v` 文件，必须同时提供：

```text
module_name/
├─ README.md                 # 责任、接口、时钟复位、参数和限制
├─ rtl/module_name.v         # 正式源代码
├─ sim/tb_module_name.sv     # 自动自检测试平台
├─ sim/vectors/              # 必要的黄金向量
├─ scripts/run_sim.tcl       # 可重复仿真入口
├─ scripts/synth_ooc.tcl     # 独立综合入口
├─ examples/                 # 最小正确例化和连接示例
├─ CHANGELOG.md              # 接口和行为变更记录
└─ VERIFICATION.md           # 已执行证据和未验证边界
```

`README.md` 必须给出最小例化、时钟频率范围、参数合法范围、资源/延迟概况、依赖 IP、兼容 Vivado/part，以及已知限制。接收者应能在不打开原始大工程的情况下完成模块仿真和 OOC 综合。

### 17.5 版本与兼容性

可复用模块采用 `MAJOR.MINOR.PATCH` 版本：

- `MAJOR`：端口、数据格式、时序或行为发生不兼容变化；
- `MINOR`：向后兼容地增加能力或参数；
- `PATCH`：不改变正式接口和行为的缺陷修复、注释或验证增强。

要求：

- 模块版本写在 README/CHANGELOG，不把经常变化的版本号硬编码进数据通路。
- Minor/Patch 修改不得破坏已有 testbench 和最小例化。
- 废弃接口至少保留一个迁移周期，并写明替代项和删除条件。
- IP、Vivado 或目标器件升级必须重新运行仿真、OOC 综合和必要的系统实现，不能沿用旧验证结论。

### 17.6 可重复构建与环境独立

1. 正式构建、仿真和 IP 创建必须有 Tcl/脚本入口，不依赖某个人保存的 GUI 状态。
2. 脚本必须使用工程相对路径；禁止提交 `C:\Users\...`、个人盘符安装路径或临时目录。
3. 输入、输出、失败条件和生成目录必须写在脚本头部或 README。
4. 同一受控源和工具版本应产生等价配置与结果；生成文件应有一致性或哈希检查。
5. 外部依赖必须列出名称、版本、许可证状态和获取方式，不允许“在原作者电脑上才有”。

### 17.7 独立代码评审

生产级模块进入正式集成前至少经过一次独立评审。评审者重点检查：

- 接口合同是否完整，调用者是否需要猜测；
- 模块职责是否单一，是否存在不必要耦合；
- 时钟、复位、CDC、位宽、signed 和背压是否明确；
- 错误、超时和恢复是否完整；
- 注释是否解释设计依据，而非重复语句；
- 官方 IP/XPM/原语选择是否合理；
- 自动测试是否覆盖正常、边界和失败路径；
- 是否存在未解释 warning、机器相关路径或不可复现 GUI 操作；
- 验证结论是否诚实区分仿真、实现和硬件。

作者必须先按检查表自审；评审意见必须闭环为“已修改、书面接受风险或明确阻塞”，不能口头跳过。

### 17.8 生产级完成门槛

模块只有同时满足以下条件，才能标记为“可复用”或“生产候选”：

- 接口、参数、时钟、复位、错误和限制有完整文档；
- 代码整洁，0 隐式网络、0 非预期锁存器、0 未解释位宽/signed/CDC 问题；
- 自动 testbench 和 OOC 综合均可由脚本重复运行；
- 依赖 IP、版本和许可证已记录；
- 有最小例化、验证记录和变更记录；
- 已完成独立评审；
- 若声称硬件可用，必须另有真实硬件证据。

未达到以上条件时，只能标记为“实验代码”“参考实现”或“验证候选”，不得包装成可直接复用的正式模块。
