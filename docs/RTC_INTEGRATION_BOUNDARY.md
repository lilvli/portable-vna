# RTC 后续集成边界

## 1. 结论

第一阶段仍然是可独立使用的便携 VNA：独立完成频点配置、外部或软件触发、复数点采集、扫频、校准和结果输出。RTC 仅作为后续 host 侧适配器接入，不能反向成为 VNA 底层数据通路或第一阶段 MVP 的依赖。

后续系统职责保持分离：

- 上位机/测控服务是唯一业务状态机，负责编译并冻结计划、预检、资源所有权、数据校验、保存、回放和报告。
- RTC 是实时编排层，负责协调波位、TR 窗口、频点/触发时序和 VNA 单点触发。
- VNA 是测量层，一次有效触发生成一个可关联频点的原始复数结果。
- 波控机和转台必须提供真实动作或稳定证据；只有通信成功时，不能把动作完成当成已确认事实。

## 2. 第一阶段必须预留、暂不实现的接口

### 2.1 触发和状态接口

1. 外部单点触发输入：明确电平标准、有效边沿、最小脉宽、允许抖动和输入保护。
2. `READY/BUSY/DONE` 或等价状态：必须能区分可接收触发、正在采集和结果已经锁存。
3. 严格的一触发一点语义：一次有效触发只生成一个频点的复数测量，不得隐式连扫多个频点。
4. 超时、取消和故障：触发丢失、重复触发、采集超时、数据无效和内部溢出必须有明确错误状态。
5. `HOLD`/安全 RF 状态：停止后禁止继续产生未授权激励或触发。

第一阶段可以先通过 FPGA 寄存器和调试 GPIO 验证这些接口，不要求实现 RTC UDP 协议。

### 2.2 频点和复数数据接口

建议在 VNA 控制协议中预留以下抽象能力：

```text
configure_point_plan(frequency_axis | one_point)
arm_external_trigger()
read_complex_sample()
cancel()
enter_hold()
get_status()
```

每个结果至少包含：

- `run_id`、`request_id` 和点序号；
- 频率值与 `frequency_index0`；
- 原始复数 `R`、`A`，或等价的同步 I/Q；
- 积分长度、削顶/链路/数据有效标志；
- 触发与结果时间戳；
- 故障码和结果来源。

VNA 应保留原始复数数据，幅度、相位、`A/R`、S 参数和校准结果属于派生量。

### 2.3 外置信号源握手

如果后续采用“外置信号源 + 直采接收机”，必须提供频率切换完成或源稳定握手，并明确它与接收机采样窗、RTC 触发之间的时序。固定 `sleep` 只能作为有来源、有单位和有上限的临时保守等待，不能作为已确认同步。

最终 VNA 集成上下变频后，同样必须由 VNA 对外报告频率合成器/本振锁定、变频通道切换和滤波器稳定后的 `READY`（或等价 `frequency_settled`）证据。RTC 或 host adapter 不得仅依赖无证据的固定延时猜测变频已完成。

## 3. 第二阶段 host RTC adapter 需求

### 3.1 适配器责任

host RTC adapter 负责：

- 显式建立和关闭 RTC UDP 会话；软件启动不得自动连接真实设备。
- 实现 RTC V0.7 帧编解码、CRC16-CCITT-FALSE、状态和错误码映射。
- 使用 `PING -> GET_INFO -> GET_STATUS` 完成最小握手和能力预检。
- 区分 ACK、NACK、DONE、FAULT 和天线结果；ACK 仅表示请求被接受或查询完成。
- 保持单一未完成事务；查询类命令允许同一原始帧有界重发。
- 对 ARM、触发、停止和天线透明转发等副作用命令最多发送一次；超时后先查询状态/结果。
- 结果仍无法确认时保存 `UNKNOWN_RESULT`，不得通过重复副作用命令猜测恢复。
- 显式映射 `beam_index0` 与 RTC 一基地址 `rtc_address1`，禁止混用。
- 管理资源所有权、暂停、正常停止、立即停止和故障收尾。

adapter 不负责 SOL 校准、方向图数学、HDF 结构或报告生成。

### 3.2 冻结拓扑

后续 RTC 自动测试使用独立拓扑：

```text
test_topology = RTC_VNA_POINT
beam_control  = RTC_AUTOMATIC
B >= 1
F >= 1
```

`SOFTWARE_VNA_SWEEP + SOFTWARE_DIRECT` 和 `DEBUG_SCAN` 是另外两条独立拓扑。三者不得在运行时静默推导、自动切换或混用。

同一空间点、同一波位下完整的 `F` 个复数频点才形成一个确认采集包：

```text
for beam_index0 in 0 .. B-1
    切换波位并确认有效应答/完成保守稳定等待
    for frequency_index0 in 0 .. F-1
        协调频率
        触发 VNA 单点采集
        读取并校验一个复数结果
    F 点全部齐全后提交该波位采集包
```

任一频点缺失、重复、索引错误、部分数据、波位证据缺失或保存失败，都不得推进主进度。

### 3.3 进度和完成语义

方向图主进度：

```text
expected_acquisition_total = R * A * max(B, 1)
vna_external_trigger_total = expected_acquisition_total * F
```

频点触发是包内子进度，主进度分母不能再次乘以 `F`。采集达到 100% 也不等于测试完成；只有最终结果校验、设备安全收尾和原子发布全部成功后，状态才允许进入 `COMPLETED`。

## 4. RTC、转台、波控和便携 VNA 台架矩阵

| 阶段 | 设备组合 | 主要验证内容 | 最低通过证据 |
|---|---|---|---|
| P1 | 便携 VNA + fake host | 独立扫频、SOL 校准、复数数据闭环 | 同一原始 R/A 可重复重算；真实硬件项单独记录 |
| P2 | 便携 VNA fake + fake RTC adapter | 单频、单波位、ACK/DONE/FAULT/超时语义 | 自动测试覆盖正常、重复、丢失、UNKNOWN 和取消路径 |
| P3 | 便携 VNA + RTC，单空间点 | 一次 RTC 触发恰好对应一次 VNA 频点结果 | 触发计数、结果计数、索引和时间戳一一对应 |
| P4 | 便携 VNA + RTC + 波控 | 完整 `F` 点 × `B` 波位包、地址映射和错误关闭 | 任一缺点不提交包；`beam_index0` 与 `rtc_address1` 可追溯 |
| P5 | 加入转台 | `R × A` 单向逐行扫描、回起点、停稳、暂停和停止 | 计划角、实际角、停稳证据及主进度一致 |
| P6 | 全真实设备 + 逻辑分析仪/示波器 | TR 边沿、触发电气、延迟、抖动和最坏时序 | 实测满足窗口与安全余量；故障路径不会继续推进 |

连续扫描在 ARM 前还必须证明：

```text
rtc_task_worst_case + safety_margin < positioning_pulse_interval
positioning_pulse_interval = azimuth_step_deg / abs(scan_speed_deg_per_s)
```

下一定位脉冲到达时 RTC 仍忙，必须进入 `FAULTED` 或 `UNKNOWN`，不能丢弃、合并或事后补做并冒充正常采样。

## 5. 数据和追踪最低要求

每个完整采集包至少关联：

- `run_id`、`measurement_id`、请求/事件序号；
- 测试拓扑、空间行号、方位采样索引；
- 计划角和转台实际回读角；
- `beam_index0` 和 `rtc_address1`；
- `frequency_index0` 和完整频率轴；
- TR 窗口 `TX` 或 `RX`、极化和测量路径；
- 原始复数数据、故障状态和来源证据。

主机负责结果保存、检查点、只读重开校验和最终原子发布。RTC 不拥有数据文件结构、校准数学或补偿算法。

## 6. 验证边界

现有 RTC 协议、状态机和离线闭环可以作为设计和 fake 测试依据，但不构成 RTC、波控、转台和便携 VNA 的真实组合验收。真实 UDP、触发电气、TR 边沿、转台停稳和 RF 链路必须按 P3–P6 逐级验证。
