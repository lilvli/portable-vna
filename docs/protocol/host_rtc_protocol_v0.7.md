# 上位机—RTC通信协议 V0.7（全32字节字段定义版）

状态：固定32字节控制与应答帧；波位表仅保留写入和读取指令；每个固定指令完整定义D0～D31
日期：2026-08-03

## 1. V0.7设计基线

本协议定义天线测试上位机与RTC实时同步控制器之间的UDP应用层通信。V0.7采用以下确认规则：

- 普通请求、查询、ACK、NACK、DONE、FAULT和普通天线结果均使用固定32字节帧。
- `D0～D31`统一表示整帧的32个字节，不再把22字节载荷单独编号为D0～D21。
- 固定帧中的原始数据区为`D8～D29`，共22字节，可完整容纳一帧原始波控请求或应答。
- 删除请求序列号；上位机同一时刻只允许一个未完成事务。
- 波位存储只保留`WRITE_WAVE_ENTRY (21)`和`READ_WAVE_ENTRY (24)`两个指令。
- 删除`BEGIN_WAVE_LOAD (20)`、`END_WAVE_LOAD (22)`、`ABORT_WAVE_LOAD (23)`、`GET_WAVE_TABLE_INFO (25)`和`CLEAR_WAVE_TABLE (26)`。
- 波位写入按地址直接生效，不再使用开始、整表CRC、提交或回滚流程。
- 23～286字节FLASH等特殊天线请求仍使用独立变长数据帧；其ACK和结果回读仍为固定32字节。
- RTC不修改、不重新计算天线原始帧内部字段或内部CRC。

## 2. 网络、字节序与CRC

| 项目 | 定义 |
|---|---|
| RTC IP地址 | `192.168.10.10` |
| 子网掩码 | `255.255.255.0` |
| RTC UDP监听端口 | `50000` |
| UDP映射 | 一个UDP数据报承载一个完整RTC应用帧 |
| 多字节字段 | 大端 |
| 固定帧长度 | 32字节 |
| CRC | CRC16-CCITT-FALSE |

CRC参数：

```text
Poly=0x1021
Init=0xFFFF
RefIn=false
RefOut=false
XorOut=0x0000
固定帧计算范围=D0～D29
CRC发送顺序=高字节、低字节
```

## 3. 固定32字节帧

### 3.1 通用布局

| 整帧字节 | 长度 | 通用字段 | 定义 |
|---|---:|---|---|
| D0～D1 | 2 | SOF | 固定`A5 5A` |
| D2～D3 | 2 | LENGTH | 固定`00 20`，表示32字节 |
| D4 | 1 | OPCODE | 请求、ACK或事件操作码 |
| D5 | 1 | CONTROL | 命令标志、应答状态或结果分片信息 |
| D6～D7 | 2 | AUX | 地址、索引、长度或辅助参数 |
| D8～D29 | 22 | DATA | 命令参数、查询结果或完整22字节原始帧 |
| D30～D31 | 2 | CRC16 | 覆盖D0～D29，大端 |

所有命令表中的“填0”均为必须要求。接收端必须拒绝保留位非0的请求，以便后续版本扩展时保持确定行为。

### 3.2 ACK规则

- 普通成功ACK的`D4 = 请求OPCODE | 0x80`。
- ACK的D5～D29必须采用相应命令表定义，不能返回未初始化数据。
- ACK只表示请求被接受或查询已完成；ARM、软件触发和天线透明转发的最终结果另由DONE、FAULT或ANTENNA_RESULT报告。

### 3.3 无序列号事务规则

- 上位机严格使用停止等待方式，同一时刻只发送一个等待应答的请求。
- 查询类命令允许在ACK超时后原帧重发，默认100 ms，最多3次。
- ARM、SOFTWARE_TRIGGER、停止、接口切换和天线发送等副作用命令不得盲目自动重发；必须先查询状态。
- 外层请求CRC可以作为最近请求内容指纹，但不是请求序列号。

## 7. 波位存储：仅写入与读取

### 7.1 存储规则

- 第一版波位存储深度为512条，每条22字节。
- 地址范围为1～512；协议地址0无效。
- RTC为每个地址维护有效位。上电或复位后所有有效位清0，不要求物理清零BRAM数据。
- `WRITE_WAVE_ENTRY`成功后对应地址立即有效，可覆盖原有内容。
- 不要求按地址顺序写入，不存在BEGIN、END、整表CRC、提交或回滚。
- `READ_WAVE_ENTRY`读取未写入地址时返回`WAVE_ENTRY_NOT_VALID`。
- RUNNING、ARMED或ANTENNA_DEBUG状态禁止写入；RUNNING或ANTENNA_DEBUG状态禁止读取。
- ARM时若`B>0`，RTC检查`A0～A0+B-1`每个地址均有效，否则拒绝ARM。

## 11. 自动测试与TR规则

RTC循环顺序保持为信号源外层、波位中层、VNA触发内层：

```text
等待转台定位上升沿或软件触发
  for source_index = 1 .. max(S, 1)
    若S>0：触发信号源并等待握手
    for beam_offset = 0 .. max(B, 1)-1
      若B>0：读取地址A0+beam_offset的22字节帧并发送
      for vna_index = 1 .. V
        等待TR测量窗口和VNA_RDY
        输出1 μs VNA_TRIG
        等待VNA_RDY重新上升
```

- `S=0`表示不使用外置信号源，可由E5080B直接提供射频。
- `B=0`表示不发送波位帧。
- `V`范围1～65535，不允许为0。
- TR由RTC输出；TX为高电平窗口，RX为低电平窗口，同一周期只测一种模式。
- TR高电平脉宽1～655 μs，占空比不超过30%；占空比0关闭TR。
- VNA延时0～655 μs；RX采集必须在下一TR上升沿前结束。

## 12. UDP恢复规则

- PING和全部GET查询允许原帧重发。
- WRITE_WAVE_ENTRY为按地址覆盖写；同地址相同内容重发安全，同地址不同内容视为新的写入请求。
- ARM、SOFTWARE_TRIGGER、STOP、SET_ANTENNA_INTERFACE、ANTENNA_TRANSFER_22和ANTENNA_BULK_TRANSFER超时后先GET_STATUS，不自动重发。
- 天线结果帧丢失时使用GET_ANTENNA_RESULT_INFO和READ_ANTENNA_RESULT_CHUNK恢复，不能重发原始天线副作用指令。
- 网络断开不自动停止已经开始的RTC任务。

## 14. FPGA实现建议与V0.7变化

建议波位存储实现：

```text
wave_ram       : 512 × 176 bit
wave_valid     : 512 × 1 bit
WRITE(21)      : address检查 → 写22字节 → valid置1 → ACK A1
READ(24)       : address/valid检查 → 读22字节 → ACK A4
ARM            : 检查A0～A0+B-1全部valid
```

V0.7相对V0.6的主要变化：

- `D0～D31`统一为整帧字节编号。
- 每个固定请求、成功ACK和事件表完整覆盖D0～D31。
- 波位存储只保留WRITE和READ两个操作码。
- 删除波位加载会话、整表CRC、提交、回滚、信息查询和清空命令。
- 写入按地址立即生效，读取未写地址返回明确错误。
- LOADING状态和波位表管理状态机不再需要。
